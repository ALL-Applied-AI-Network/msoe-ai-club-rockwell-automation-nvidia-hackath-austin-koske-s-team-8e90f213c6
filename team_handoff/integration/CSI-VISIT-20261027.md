## 4. On-site 90-minute run sheet and prospective sequence

| Minutes | Work | Record / decision |
| --- | --- | --- |
| 0-10 | CSI walkthrough; confirm supervisor, host, allowed feed/export and operator response | Session/host sheets; exact access and independent outcome procedure |
| 10-20 | Saved-clip smoke; then short approved capture pilot | Open/decode actual files, check framing, source clock and storage; stop to fix a bad input profile |
| 20-35 | Empty reference and independent acceptable endpoint examples, if CSI can provide them | Human evidence, camera/profile, recipe/vial IDs; separate commissioning from validation |
| 35-65 | Frozen prospective fills and staff-approved normal recipe change | Every attempt, native recording, predictions/QA, independent notes and uncertainty |
| 65-78 | Software failure/reset checks; one operator review/response | Stale-frame/reference handling and source-pinned journal; label injected cases software tests |
| 78-90 | Export, inspect and back up; short demonstration recording | Raw recordings, logs, forms, independent review candidates and measured limits |

**Reference procedure:** CSI/reviewer confirms an empty stationary vial under the
nozzle in the approved view, or records that no suitable reference is available.
Retain its image/hash, clock, camera/profile and physical context plus reviewer
evidence. It must precede the current frame and stay aligned. Invalidate on a new
vial/context, source/profile change, rewind or lost alignment; do not reuse an old
vial's reference by default. Repeated empty frames alone do not prove emptiness.

**Requested collection target, subject to cycle time:** two independently
accepted recipe endpoint references (A and B), followed by up to six validation
fills: A1/A2/A3 then B1/B2/B3. CSI selects and runs approved recipes/conditioning.
Record previous/current recipe, actual tank contents, physical vial ID and actual
completion. Roles are fixed before scoring; do not pick the best-looking third
vial as truth automatically. If references cannot be established, recipe verdicts
stay unavailable and the mask/QA test can continue diagnostically.

Keep models, thresholds and profile frozen during prospective scoring. A profile
or algorithm change after viewing a case turns that work into development;
reserve a new sequence for evaluation. New footage/reviews are evaluation-only,
not CSI-domain training data. Record failed/missed/unavailable cases too.

Ask CSI to explain the current sorting destinations and identify them physically.
The reported good/scrap labels conflict with earlier public descriptions; routing
and a recognized database color do not independently establish intended-recipe
acceptance. No artificial contamination, flush volume or equipment change is
prescribed by this guide.

## 5. Test matrix and measurements

| Test | What we do | What we measure / expect |
| --- | --- | --- |
| Empty and stream-only | Record natural pre-pool frames; independent human review later | False pool proposals; keep falling stream separate from accumulated body |
| First visible bottom pool | Preserve full-rate source footage across several independent fills | Reviewed first-visible interval, detection delay/misses, mask boundary IoU/Dice |
| Established / pale pool | Use naturally available colors, glare, bubbles and partial visibility | Pool mask and QA coverage; uncertain or occluded targets excluded explicitly |
| Sample-QA failure | Natural failures plus one clearly labeled software fixture with failed QA | UI must show unavailable; matching RGB must not override failed QA |
| Recipe endpoint | Compare only after accepted reference, intended recipe, physical ID and completion are qualified | Mismatches, false warnings and unavailable cases; score independent outcomes separately |
| Wrong/stale reference | Pause/switch the software source or invalidate its reference without touching cameras | Reference reset, reasons shown, old mask/recipe status not attached to a new frame/vial |
| Slow/disconnected input | Software pause/drop/delay test | Source-age indication, drops, no unbounded backlog and no stale normal verdict |
| Human response | Pin a real observation; operator acknowledges and records the approved action | Correct source/vial association, acknowledgement/response time and retained history |
| Optional final fixture | Staff-approved independent cap view if time remains | Raw slot crop and cap proposal; body damage/physical cross-camera identity remain unassessed |

**Sampling plan:** record the native source stream for review. Begin inference
at a declared 5 Hz for the stability test; increase only in a separate documented
throughput run. At 5 Hz the sampling interval alone is 200 ms, before processing and
display. This does not establish native 30 fps inference or reviewed onset accuracy.

**Suggested engineering target:** processing result freshness p95 <=500 ms at the
declared 5 Hz input, agreed with CSI/operator; this is a proposed test target, not
measured performance or a recipe/quality threshold. Record actual rate, p50/p95,
max age, drops and GPU usage. Latest GB10 CV median 16.37 ms excludes decode/network/UI
and must not be relabeled as CSI-PC or camera-to-screen latency.

Native video PTS, workstation monotonic timers and browser clocks are different
clock domains. Measure same-host receive-to-result directly. Camera-to-display
needs a verified clock mapping or independent visible timing test. If unavailable,
report the narrower measurement and leave true camera-to-display latency unknown.
Do not subtract unrelated clocks. Log reference, source and UI-rendered frame IDs.

Count distinct vials/episodes as well as correlated frames. Six fills are a pilot,
not production reliability evidence. QA availability, model confidence and mask
agreement remain separate from independent accuracy and recipe acceptance.

## 6. Evidence, closeout and CSI questions

Use a new session folder, for example `csi-20261027/session-01/`, containing
`raw/`, `host/`, `observations/`, `references/`, `reviews/`, `operator/` and
`presentation/`. Preserve raw recordings unchanged; store annotated outputs
separately. Logs retain source/frame/native PTS, RGB identity, model/config/profile
hashes, reference identity/status, raw mask/presence, QA/reasons and actual response.

**Before leaving:** replay a sample of every recording, check timestamps and
file sizes, verify one image/mask/log join and one operator record, hash outputs,
copy to an approved second location and record verification. Export every attempt
and issue. Record a short screen demonstration with the input mode labeled live,
file replay or cached. Record independent outcomes and uncertain cases; do not
manufacture a defect or human approval to complete the demo.

| Ask CSI before / at arrival | Why it matters |
| --- | --- |
| Confirm date/time, supervisor and duration | Tuesday is a target; the 90-minute sheet is not a booking |
| Which workstation, login, GPU/OS and existing Python environment can we use? | Published workstation description may differ from the assigned unit |
| What exact video/file handoff is approved? Can it be recorded/exported? | Need source method/SDK or staff handoff; no direct existing-camera permission is assumed |
| What are native dimensions/orientation/time semantics and current camera settings? | Qualify the fixed ROI/reference and measure latency honestly |
| Who confirms empty reference, acceptable recipe endpoint, physical vial ID and completion? | These are independent inputs to qualified comparison |
| Which normal recipes/changeover and operator responses are approved? | CSI runs the line; the app requests review and records what actually happens |
| What do the actual sorter destinations mean today? | Route labels are not intended-recipe truth |
| Can we retain originals and staff-provided recipe/outcome notes? | Enables independent review and a reproducible presentation |

**If only 30 minutes:** confirm access/profile; save a valid pilot clip and empty
reference evidence; process at least one fill and capture QA/operator behavior;
export/back up. Defer extra models, cap inspection and throughput sweeps.

**Presentation tie-in:** show what the AI-guided onboarding skill discovered and
which human/physical inputs it could not establish, then show the same pipeline's
actual observations. The helper checks asset hashes only; it does not qualify
references, prove deployment or approve product quality.
